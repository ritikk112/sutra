Why "both" ≈ grep

36 / 36 pure grep
Given both grep and the Sutra index and free to choose, the agent made zero sutra_* calls in all 36 trials — on the index tool's own source code. This is more extreme than the earlier 2-repo run (28/36) and is the direct reason the realistic "both" arm is indistinguishable from grep. It reflects agent tool-selection behavior: an agent explicitly told to prefer the index would be a separate experiment.

Method integrity. Arm constraints verified post-hoc from every transcript's tool calls: SUTRA_ONLY used grep 0/36 and the index 36/36; GREP_ONLY used the index 0/36. All 108 solves parsed, all 108 blind-graded, 0 violations, 0 fabrications. Repo pinned to a clean worktree at 6a1a33a so all arms saw byte-identical code. Gold authored by an 8-agent overseer workflow cross-checking grep + the index, every file:line re-verified.

Scope & limits. This measures read-only tracing on a repo already on disk — grep's home turf. It does not test cross-repo search, unfamiliar-codebase onboarding, or discovery when identifier names are unknown (the index's design strengths). One model, one repo, n=6; effect direction is consistent across 3 repos now, magnitudes still carry variance. Full write-up in REPORT.md.
