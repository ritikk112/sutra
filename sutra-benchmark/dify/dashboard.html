The finding, stated plainly: on a 75k-symbol repo Sutra used more tokens per run — its sutra_search results are token-dense, while grep output is compact. But it reached equally deep answers in ~half the tool calls, half the turns, half the wall-clock, and 43% less total context. On a big codebase Sutra's win moves from "fewer tokens" to "far fewer round-trips."

Caveats

  • n = 1 per repo — directional, not statistical; agent behavior is stochastic.
  • Equal-quality is qualitative — both answers were independently correct and deep; the grep agent found a NaN-zip embedding bug the index agent didn't, and vice-versa. No separate grader scored them.
  • Reported vs fresh tokens — subagent_tokens weights cache opaquely; treat the two token lenses as distinct, not contradictory.
  • Total context is cache-dominated — it best captures "total work," but is the least directly comparable metric across runs.
  • Checkout aligned — the on-disk dify was fetched/checked-out to the exact indexed commit (d67123e) before running, so both agents saw identical code.
